# claude-code-action 仕様台帳

調査対象は GitHub Action `anthropics/claude-code-action`(公開リポジトリ)の公開仕様。一次情報は同リポジトリの
`action.yml`(inputs/outputs 定義)、`README.md`・`docs/**/*.md`、公開ソース(TypeScript)、および第三者公開リポジトリでの実測。
**Claude Code 一般の挙動についての知識は根拠にしていない。** 「Claude Code ができること」と「この Action が公開している
設定・出力で到達・観測できること」は別物として扱い、後者だけを記載した。区別できない項目、公式に記載の無い項目は
状態列を `公式に未文書化` とした(`未調査` ではない)。

状態は `確認済み` / `公式に未文書化` / `取得不能` / `未調査` のいずれか(空欄なし)。

## 出力の構造

- Step Summary は常に `## Claude Code Report` を最上位見出しとし、以後 `## 🚀 System Initialization` / `## ⚙️ System Message` / `## 👤 User` / `## ✅ Final Result` の H2 サブセクションと、ツール呼び出し1回ごとの `` ### 🔧 `{toolName}` `` という H3 見出しで構成される(`src/entrypoints/format-turns.ts`)。
- ツール呼び出しの結果は `**Parameters:**` に続くフェンス付き ```json``` ブロックと、`**Result:**` に続く言語自動判定(`json`/`python`/`javascript`/`bash`/`diff`/`html`/`markdown`/`text`)のフェンスコードブロックという固定構造を持つ(`detectContentType()`)。
- Step Summary の各セクションは `---\n\n` の水平線で区切られる。
- 追跡コメント本体は「機械生成ヘッダ行(`**Claude finished ...**` または `**Claude encountered an error**` + リンク列)」→ 空行 → `---` → 「モデル自身が書く自由記述本文」という2層構造に固定されている(`updateCommentBody()`)。ヘッダとモデル本文の境界は常にこの `---` である。
- モデル本文側の書式は create-prompt テンプレートの指示によって規約化されている: セクション見出しは `###`(h3)固定・h1禁止、タスク進捗は `- [ ]`/`- [x]` のチェックリスト、末尾に必ず `[View job run](...)` 形式のジョブリンクを含める、という指示が本文に明記される(`src/create-prompt/index.ts`)。
- sticky コメントの同一性判定は本文に埋め込む HTML コメント等のマーカーには依存せず、コメント投稿者の `user.id`/`user.type`+`login`、または本文の完全一致で行われる(`create-initial.ts`)。本文中に「これは追跡コメントである」ことを示す隠しマーカー文字列は公開ソース中に見つからなかった。
- `execution_file` はフォーマット済み文書ではなく、Claude Agent SDK の生メッセージ配列(`SDKMessage[]`)をそのまま JSON シリアライズしたものであり、Step Summary/追跡コメントはいずれもこのファイルを読んで**別々に**再構成した派生物である。
